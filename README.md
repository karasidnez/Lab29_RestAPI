## Краткое описание работы
В ходе лабораторной работы изучены принципы REST и создан полноценный RESTful API на ASP.NET Core с использованием Controller-based подхода. Реализован полный CRUD для ресурса `Task` (задачи), добавлены маршруты поиска, фильтрации по приоритету, статистики и сортировки. Освоены DTO, корректные HTTP-статусы, тестирование через Swagger UI и расширение REST Client в VS Code, а также настройка CORS.

## Список всех реализованных маршрутов

| Метод | URL | Действие | HTTP-статусы |
|-------|-----|----------|---------------|
| GET | `/api/tasks` | Получить все задачи (с фильтром по `?completed=true/false`) | 200 OK |
| GET | `/api/tasks/{id}` | Получить задачу по ID | 200, 404 |
| POST | `/api/tasks` | Создать новую задачу (принимает `CreateTaskDto`) | 201, 400 |
| PUT | `/api/tasks/{id}` | Полностью обновить задачу (принимает `UpdateTaskDto`) | 200, 400, 404 |
| DELETE | `/api/tasks/{id}` | Удалить задачу | 204, 404 |
| PATCH | `/api/tasks/{id}/complete` | Переключить статус `IsCompleted` (toggle) | 200, 404 |
| GET | `/api/tasks/search?query={text}` | Поиск по заголовку/описанию (без учёта регистра) | 200, 400 |
| GET | `/api/tasks/priority/{level}` | Фильтр по приоритету (`Low`, `Normal`, `High`) | 200, 400 |
| GET | `/api/tasks/stats` | Статистика: общее кол-во, выполненные, невыполненные, по приоритетам | 200 |
| GET | `/api/tasks/sorted?by={field}&desc={bool}` | Сортировка по `priority` или `createdAt` | 200 |

## Итоговая таблица ASP.NET Core Controller-based API

| Аспект | ASP.NET Core Controllers |
|--------|--------------------------|
| Маршруты | `[HttpGet]` атрибут над методом |
| Группировка маршрутов | Класс-контроллер |
| Базовый URL | `[Route("api/[controller]")]` |
| Параметр пути | `(int id)` — параметр метода |
| Параметр запроса | `[FromQuery] bool? completed` |
| Тело запроса | `[FromBody] CreateTaskDto dto` |
| Ответ 200 | `return Ok(data)` |
| Ответ 201 | `return CreatedAtAction(...)` |
| Ответ 404 | `return NotFound(...)` |
| Ответ 204 | `return NoContent()` |
| Типизация данных | Строгая (C#) |
| Документация | Swagger — устанавливается отдельно |

## Главные выводы

1. **REST — не протокол, а архитектурный стиль.** Те же принципы работают с любым языком и фреймворком. Клиент-серверная независимость, stateless, единый интерфейс через HTTP-методы — ключевые требования к RESTful API.

2. **Контроллер в ASP.NET Core = Router в Express, но с автоматической документацией и строгой типизацией.** Атрибуты маршрутизации и встроенная привязка параметров значительно упрощают создание API по сравнению с ручным разбором запросов.

3. **DTO защищает API от некорректных данных:** клиент передаёт только то, что сервер разрешает принять. Это позволяет скрыть служебные поля и валидировать входные данные на уровне контракта.

4. **Swagger UI позволяет тестировать API без Postman и без написания тестового JavaScript-кода.** Автоматическая генерация интерактивной документации ускоряет разработку и отладку.

5. **Правильные HTTP-статусы — часть «контракта» API.** Клиент  должен понимать, что произошло, по коду ответа (200, 201, 400, 404, 204 и т.д.), а не только по наличию тела ответа.
